# Code Review Skill

변경된 코드를 다음 4가지 관점에서 리뷰한다.

## 리뷰 관점

### 1. 보안
- SQL/Command/XSS 인젝션 패턴
- 하드코딩된 시크릿 (API 키, 비밀번호, 토큰)
- 부적절한 에러 정보 노출
- 안전하지 않은 역직렬화

### 2. 성능
- N+1 쿼리 패턴
- 불필요한 반복문 내 I/O
- 메모리 누수 가능성 (이벤트 리스너 미해제, 클로저)
- 비효율적인 데이터 구조 사용

### 3. 가독성
- 네이밍 컨벤션 일관성
- 함수/메서드 길이 (50줄 초과 시 분리 권장)
- 매직 넘버/스트링 사용
- 주석 필요성 (자명하지 않은 로직)

### 4. 유지보수성
- 중복 코드 (DRY 위반)
- 높은 결합도
- 테스트 커버리지 누락
- 에러 처리 누락

## 리뷰 대상

$ARGUMENTS 가 지정되면 해당 파일/디렉토리를 리뷰한다.
지정되지 않으면 `git diff --name-only`로 변경된 파일을 자동 탐지하여 리뷰한다.

## 출력 형식

```
## 리뷰 결과

### Critical (즉시 수정 필요)
- [파일:라인] 설명

### Warning (개선 권장)
- [파일:라인] 설명

### Good (잘된 점)
- 설명
```
